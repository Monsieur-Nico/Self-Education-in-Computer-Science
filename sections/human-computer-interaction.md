# Human-Computer Interaction

## What to Expect

This section is about the side of computing that isn't code at all: how people actually use — and struggle with — the software you build. You'll cover interface design principles, how to run a design process centered on real users rather than guesses, usability testing, and accessibility.

Topics covered:

- Principles of user interface design
- User-centered design processes
- Usability testing and evaluation
- Interaction design
- Information visualization
- Accessibility

This is one of the lightest-prerequisite sections in the curriculum — it's placed here in the sequence because it pairs naturally with the practical building you've been doing, but there's nothing stopping you from tackling it earlier if design interests you more than systems programming does.

## What to Prepare

**Prerequisites:** [Introduction to Computer Science](/#introduction-to-computer-science-8-12-weeks) — that's it. This section is intentionally accessible early; it doesn't build on the programming-heavy sections the way most others do.

A few things worth knowing going in:

- **This section rewards observing real people, not just reading theory.** Usability testing in particular clicks a lot faster once you've actually watched someone else struggle with an interface you thought was obvious.
- **"Don't Make Me Think" is a fast, opinionated read** — it won't take nearly as long as the Coursera specialization, and it's worth reading early since its ideas will keep showing up as you go through the rest of the section.
- **Accessibility isn't a niche add-on topic here** — treat it as core to interaction design, not an afterthought, even though it's listed last.
