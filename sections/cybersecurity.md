# Cybersecurity

## What to Expect

This section is about thinking like an attacker in order to build systems that resist attack — network security, cryptography, how authentication and access control actually get implemented (and get implemented badly), and how to reason about risk rather than chase every possible threat equally. It draws directly on the operating systems and networking material from Computer Architecture and Systems, applied through an adversarial lens.

Topics covered:

- Network security
- Cryptography
- Authentication and access control
- Malware analysis and detection
- Security risk assessment and management

Expect a mix of conceptual material (how cryptographic primitives work, why a given attack is possible) and practical exercises (finding and understanding real vulnerabilities) — this isn't a purely theoretical section.

## What to Prepare

**Prerequisites:** [Programming Fundamentals](/#programming-fundamentals-4-6-weeks), [Computer Architecture and Systems](/#computer-architecture-and-systems-8-12-weeks) — you need a working mental model of how operating systems and networks function before you can reason about how they get attacked.

A few things worth knowing going in:

- **Security is a mindset shift, not just new facts to learn.** A lot of this section is learning to ask "how could this be abused?" about systems you previously just took for granted as working correctly.
- **Security Engineering (the book) is genuinely huge** — 1,200+ pages and the standard reference in the field, but not something to read cover to cover before moving on. Use it as a companion to dig deeper on specific topics as they come up in the course.
- **Only test what you have explicit permission to test.** If you start exploring beyond the course's own labs/exercises, stick to platforms built for that (e.g. deliberately vulnerable practice environments) — never systems you don't own or haven't been authorized to test.
