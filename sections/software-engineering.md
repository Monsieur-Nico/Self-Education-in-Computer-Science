# Software Engineering

## What to Expect

Everything up to this point has been about writing code that works. This section is about what it takes to build and maintain software as more than a solo, one-off exercise: how projects get planned and managed, how requirements get gathered (and inevitably change), how testing actually gives you confidence rather than busywork, and why software tends to get harder to change over time rather than easier.

Topics covered:

- Software development life cycle
- Software project management
- Requirements engineering
- Testing and quality assurance
- Software maintenance and evolution

This section is less about new technical skills and more about process and judgment — it will make more intuitive sense if you've already felt the pain of an unplanned project or an untested change breaking something, which is exactly what the earlier sections were for.

## What to Prepare

**Prerequisites:** [Programming Fundamentals](/#programming-fundamentals-4-6-weeks), [Data Structures and Algorithms](/#data-structures-and-algorithms-12-16-weeks) — you should have written enough code by now to have personally experienced a project getting messy as it grew.

A few things worth knowing going in:

- **This is a lighter coding load than recent sections.** Expect more reading, writing, and process-thinking than implementation — that's the nature of the topic, not a sign you're missing something.
- **The Mythical Man-Month is 50+ years old and still assigned everywhere** in this field for a reason — the specific technology it describes is dated, but the observations about people, communication, and estimation hold up. Read it for the ideas, not as a how-to guide.
- **Try applying this section to a real project of your own**, even a small one — requirements, a rough plan, some tests — rather than only reading about the concepts in the abstract. It's where this material actually sticks.
